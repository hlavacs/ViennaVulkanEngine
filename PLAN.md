Add ImGui support as the engine’s user-facing GUI system, exposed only through the `vve` facade and not through implementation-specific namespaces. The facade should provide a small `GuiSystem` API that lets user applications create simple immediate-mode UI each frame, preferably through a callback or frame-scope function, while keeping all ImGui backend setup, renderer integration, font upload, descriptor allocation, input forwarding, and shutdown inside the engine implementation. The simple engine implementation should initialize ImGui for SDL and Vulkan, route SDL input events into ImGui, add a GUI render pass to the render graph after the main color pass and before presentation, and render ImGui draw data into the active window target without requiring the application to know about Vulkan or ImGui backend objects. Keep the public API minimal and educational, for example allowing the game example to call something like `world.get<vve::GuiSystem>().draw([] { ImGui::Begin("Game"); ImGui::Text("Vienna Vulkan Engine"); ImGui::End(); });` or an equivalent facade-controlled pattern. Update the game example so it opens a small ImGui window showing basic runtime information such as frame count, active renderer, light toggles, and camera position, without changing the existing keyboard controls. Add tests or a lightweight verification path showing that the GUI system can be initialized, accepts a frame callback, contributes a GUI pass to the render graph, and does not run when no window or renderer is available. Keep the implementation compact, avoid exposing unnecessary ImGui/Vulkan details in the facade, and make sure the game target compiles and runs with the new GUI window visible.
