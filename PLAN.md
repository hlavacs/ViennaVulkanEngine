 Implement multi-light shadow-map support for the simple forward renderer in small, verifiable stages. Keep the public `vve` facade compact and educational, and keep Vulkan-specific details inside the simple implementation. Do not attempt to render the scene only once for all lights in the mathematical sense; instead, use one organized shadow submission/graph stage that can render the same scene geometry repeatedly into multiple light-space depth targets. Start by supporting multiple shadowed spot lights, because each spot light needs only one projection. Add a shadow-map atlas or depth texture array owned by the renderer, allocate one shadow slot per shadow-casting spot light, store each light’s view/projection matrix and atlas layer or viewport, and render scene depth once per shadowed light into the corresponding target. Keep the implementation simple first: a small fixed maximum number of shadowed lights is acceptable, and non-shadowed lights may still contribute lighting normally. Extend the forward shader data so the color pass can sample the correct shadow map for each light and combine lighting from multiple lights. Add debug data that records, for at least one test vertex or pixel per light, the light-space position, selected shadow slot, sampled shadow depth, computed depth, bias, and final shadow factor, and write this data to a text file or downloadable buffer for verification. Update the light/shadow debug example so it contains at least two spot lights with clearly different positions and directions, producing distinct visible shadows on the test plane. Add tests or verification output proving that each light receives a unique shadow slot, that the render graph contains a shadow stage before the color stage, and that the color pass uses the per-light shadow information. After spot-light shadows work, prepare the architecture for directional and point lights: directional lights may use their own 2D shadow map or atlas slot, while point lights should be deferred until later because they need six views per light, usually via cubemap or texture-array layers. Minimize LOC, avoid unnecessary new classes, prefer small structs and STL containers, and keep the renderer factory and render graph renderer-agnostic while letting the forward renderer provide its own shadow passes.
