Implement the missing public bridge between imported assets and renderable objects. Keep the API in the `vve` facade only, and do not expose implementation namespaces or renderer internals. Add a clear facade operation such as `RenderSystem::instantiateScene(SceneHandle scene)` or `RenderSystem::addScene(SceneHandle scene)` that takes a scene previously loaded with `AssetSystem::loadScene(path)` and creates renderable objects from its nodes, meshes, materials, textures, transforms, lights, and cameras. The function should return a public handle such as `RenderSceneInstanceHandle` plus, if useful, a list of created `RenderObjectHandle`s. Preserve the separation of concerns: `AssetSystem` owns imported descriptors and raw asset data; `RenderSystem` owns render objects, render resources, visibility, transforms, and GPU upload state. For every imported mesh node, create or reuse render-side mesh and material resources, compose node transforms through the scene hierarchy, create render instances, register public `RenderObjectHandle`s, and store a mapping from scene instance to its render objects. Imported materials should use base color and texture data where available; imported textures should be resolved using the paths already stored by the asset system and should reuse render-side texture resources when possible. Imported lights and cameras should optionally be applied to the render scene through a small facade options object, for example `SceneInstantiationOptions`, with defaults that instantiate geometry and ignore cameras/lights unless explicitly enabled. Add lifetime rules: removing a render scene instance removes all render objects created from it; removing an asset scene should fail while render scene instances still depend on it; `purgeUnusedAssets()` should remove render resources no longer referenced by live render objects. Add public query functions to inspect the connection, such as `sceneInstanceObjects(instance)`, `objectSourceScene(handle)`, and `objectSourceNode(handle)`. Update examples so a loaded scene can be made visible through the public facade, and add tests proving that `AssetSystem::loadScene` creates asset descriptors, `RenderSystem::instantiateScene` creates visible render objects, transforms are composed correctly, scene-instance removal invalidates its objects, and asset scene removal fails while render instances still reference it. Keep the implementation compact, use STL containers and typed handles, avoid unnecessary new classes, and preserve the educational clarity of the simple engine.
