Implement complete public object lifetime management in the `vve` facade. Keep all application-facing APIs in namespace `vve`, keep implementation details hidden behind the selected simple engine implementation, and do not expose `vve::simple` types. Preserve the existing ECS behavior, where `ECS::create()` creates an entity and `ECS::erase(entity)` deletes the entity and all its components, but add equivalent lifetime control for rendered scene objects and loaded assets. Render object creation should return stable typed handles instead of only `std::expected<void, Error>`: `RenderSystem::addPlane`, `addCuboid`, and `addTexturedCuboid` should return a public render-object handle, and the render system should provide `removeObject(handle)`, `setObjectVisible(handle, bool)`, `objectVisible(handle)`, `setObjectTransform(handle, Transform)`, and `objectTransform(handle)`. These operations should validate handles and return `std::expected` where failure is possible. `clearScene()` should remain available and invalidate or remove all render-object handles. Asset lifetime should also be explicit: add public facade functions such as `removeScene(SceneHandle)`, `purgeUnusedAssets()`, and, if the implementation stores independent resources, removal functions for textures/materials/meshes only where safe. Scene/node/mesh/material/texture query functions must return invalid-handle errors after removal rather than silently succeeding. If a loaded scene has render instances created from it, decide and document the ownership rule: either removing the asset scene fails while instances still reference it, or it removes/purges dependent render objects as well. Prefer the safer educational rule first: fail removal while dependent render objects exist, and provide clear errors. Add minimal implementation support in the simple engine using small STL containers and typed handles; avoid unnecessary new classes. Update examples to store the returned render-object handles and demonstrate hiding, moving, and removing at least one object. Add unit tests for entity deletion, render-object creation/removal/visibility/transform, scene removal, invalid-handle behavior, and `clearScene()` invalidation. Keep the API compact, strongly typed, and suitable for educational use.
