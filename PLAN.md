Implement full multi-light shadow support for the simple forward renderer, including spot lights and point lights. Keep the public `vve` facade compact and educational, and keep all Vulkan-specific details inside the simple implementation. Use one organized shadow stage in the render graph before the color pass, but do not assume the scene can be rasterized only once for all lights; each shadowed light view still needs its own light-space depth rendering. Support multiple shadowed spot lights first with one 2D shadow-map atlas or depth texture array slot per spot light. Then add full point-light shadow support using cubemap-style rendering: each shadowed point light needs six shadow views for the ±X, ±Y, and ±Z directions, stored either in a cubemap array or in six layers of a depth texture array. Use a small fixed maximum number of shadowed point lights at first to keep the code understandable. Store per-light shadow metadata, including light handle or index, light type, shadow slot, layer range, view/projection matrices, near/far planes, bias, and resolution. Extend the forward shader data so the color pass can evaluate multiple lights, sample the correct spot-light shadow map or point-light cubemap/layer set, and combine all lighting contributions correctly. For point lights, compute the vector from light to shaded point, select or sample the cubemap face consistently, compare radial depth using the same near/far convention used by the shadow pass, and apply a small configurable bias. Update the light/shadow debug example to include at least two spot lights and at least two point lights at different positions, with visibly distinct shadows on the plane and cuboid. Add debug verification output for every shadowed light type: selected shadow slot, selected point-light face where applicable, world position, light-space or radial depth, sampled depth, depth delta, bias, and final shadow factor. Add tests or verification checks proving that each shadowed light receives unique atlas/cubemap layers, that the render graph schedules shadow generation before the color pass, that point lights allocate six layers each, and that non-shadowed lights still contribute normally. Keep the implementation minimal: avoid unnecessary new classes, prefer small structs and STL containers, avoid duplicating spot and point shadow code where a shared helper is clearer, and keep renderer selection/render graph wiring renderer-agnostic while letting the forward renderer provide its own shadow passes.
