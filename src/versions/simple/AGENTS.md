# AGENTS.md

## src/versions/simple

The simple engine should be the bare engine minimum. Just to render objects, and have lights and shadows. 
- Use a simple scene graph. Do not use render or task graphs.
- Use the existing helpers instead of reimplementing them: Handle, Vector, ECS, Math and the strong types come from the facade vocabulary modules (re-exported through Types.ixx), Graph and Tree are local (Graph.ixx).
- `Vector<T>` aliases `std::vector<T>` with contiguous storage. Growth can invalidate element pointers; reserve before taking them or look them up again afterwards. Mesh editing re-looks up the mesh after cloning; instance storage is separate.
- Create empty source files as soon as possible.
- No virtual layer, keep things explicit for the time being.
- Keep the code as simple as possible. 
- Always prefer STL, be it containers, algorithms, etc. Use STL instead of new classes if possible.
- Keep number of new types, structs at a minumum.
- The best class is the class not needed. The same is true for structs, types, enums, functions, etc.
- The engine should mirror the official Vulkan tutorial https://github.com/KhronosGroup/Vulkan-Tutorial (there base the renderer on en/16_Multiple_Objects) in structure.
- It should use SDL3, VMA, Assimp, Slang, dynamic rendering, Vulkan profiles. (Current code: SDL3, VMA, Assimp, stb_image, Slang, dynamic rendering and vvppl for post-processing; Vulkan profiles are not used yet, Vulkan/Device.ixx checks the required queue family and features directly.)
- It should enable loadig assets and rendering multiple objects.
- Devices must support Vulkan 1.3, VK_KHR_swapchain, dynamicRendering and shaderSampledImageArrayDynamicIndexing; the instance still requests VK_API_VERSION_1_4, while ImGui uses VK_API_VERSION_1_3. Device.ixx evaluates these requirements before selection and reports rejected device names and versions if none qualifies.
- It should provide a simple, minimal debugging layer that transports debugging information for Slang, SDL3 windows, rendering output. 
- It should use the light shadow debug example behavior that produces known output that can be stored in a PNG for automatic analysis.
- The debugging example light shadow debug should not be part of the simple engine, but be in the examples folder. It is examples/light_shadow_debug; CTest runs it as LightShadowDebugExample, and it writes bin/<variant>/verify/light_shadow_debug.txt and light_shadow_debug.png.
- The LLM should ingest this output and analyse whether the current version produces the correct result.
- The goal is to let an LLM do the heavy lifiting, to the LLM should be able to reliably detect bugs through the debuggin output.
- Debugging information that is collected and moved e.g. from GPU to CPU should be kept at a minimum necessary. 
- Add code comments and function and class headers. 
- At the start of each file provide an overviw over the functional objects (classes, enums, types, structs, ...) and their purpose in this file.
- The engine should not use Python anywhere, also not for testign. It can use cmd or bash scripts.
- The Renderer should be a simple forward renderer. As Vulkan render path and Slang expample vertex and pixel shaders, use the Vulkan Tutorial and adapt if needed.

## Layout

- Types.ixx (VVEngine.Simple.Types): math aliases, RenderVertex (48 bytes; a zero normal makes the shader use the face normal, a zero tangent skips normal mapping), MaterialTextureSemantic, EmbeddedImage, MaterialFactors. Re-exports VVEngine.Types and VVEngine.ECSContainer.
- Graph.ixx (:Graph): DAG and Tree helpers used by the asset scene tree. A handle set provides membership and an order vector preserves creation order independently of handle values; `nodes()` returns that order. Graph nodes carry no labels; asset nodes retain their imported names.
- Window.ixx (:Window): Windows, InputState, SDL3 WindowSystem. WindowDesc, WindowInfo and WindowFrameData come from VVEngine.Types. `visible = false` creates a hidden window that still renders; extents are drawable pixels. An empty renderer id or `"forward"` renders; `"none"` opts out, and any other id makes Engine::init return `Error::invalid_argument`. `init` is transactional and idempotent: it rejects repeat initialization with `Error::already_initialized`, duplicate ids with `Error::duplicate_object`, and empty ids or zero extents with `Error::invalid_argument` before any SDL call. Windows are committed together on success; failure destroys pending windows and releases only the SDL video reference acquired by that call, allowing a retry.
- Assets.ixx (:Assets): Assimp-backed AssetSystem with its Catalog (scenes, nodes, meshes, materials with factors and typed file or embedded texture sources, lights and cameras in world space). `sceneTextureCount` derives the number of distinct source paths across the scene's materials. `sceneNodes` comes from the tree in creation (pre-order) order, `nodeMaterials` from attached meshes' material handles, and vertex/index counts from mesh array sizes. `sceneWithNode` checks tree membership; imported `AssetMesh::bounds` and the facade `meshBounds()` query remain. `field()` and `sceneField()` borrow const members; count/root queries read them directly and value queries copy once at the boundary. `AssetMesh` builds one `shared_ptr<const std::vector<RenderVertex>>` at import; `ImportedAssetReadAccess::mesh_geometry` shares it with `RenderMesh`. Attribute `mesh*View()` accessors project const references from that buffer; indices remain a const span. Views are borrowed until catalog mutation or destruction, while facade queries extract owning arrays. Missing tangents still yield an empty view. Object vertex edits detach shared storage before writing, preserving catalog geometry; private edit buffers are reused. Material and mesh descriptors move into the catalog after saving their handles. Render materials store only texture-table indices with `kNoTexture` for an absent texture; the table and its lookup index retain canonical paths and colour-space identity.
- GUI.ixx (:Gui): Dear ImGui context with the SDL3 and Vulkan backends. Initialization returns `std::expected<void, Error>`; `ready()` requires both backends and fonts. Engine logs a failed setup stage once, shuts down the initialized GUI parts and continues rendering without a GUI sink. `processEvent` returns true when ImGui claims a key-down, text or mouse event, which then does not reach InputState (key-up events always do).
  Device creation enables VK_KHR_swapchain_mutable_format only when advertised. Presentation.ixx keeps the sRGB scene format and owns extra UNORM GUI views beside the existing views; both sets are destroyed before the swapchain. ImGui's pipeline uses that GUI format. Without the extension, initContext linearizes only the initial theme RGB once, leaving alpha and custom draw colours unchanged.
  `prepareFrame()` builds draw data before command recording and returns whether vertices exist; `record(cmd)` records that data only inside a needed GUI pass. User callback exceptions (`std::exception`) are logged once during preparation and recover ImGui stacks before rendering finishes; the next `Engine::step()` consumes the failure as `Error::platform_error`. Replacing the callback allows later steps to succeed.
- Engine.ixx (VVEngine.Simple): simple::Engine owns ECS, windows, assets, render system and GUI. Options: ApplicationName, MaxFrames, vve::simple::Windows; any other type is a compile error.
  `renderFrame` skips minimized windows and windows with zero drawable pixels. Their targets, camera overrides and post-processing chains remain alive, and GUI ownership stays on the first rendered window. If no window can render, the last presented-window count is zero, frame/FPS counters stay unchanged, and it waits with `SDL_WaitEventTimeout(nullptr, 100)` before returning success; the wake-up event remains queued for the next poll. If all windows are initially minimized, GPU initialization waits until a window can render.
- Scene.ixx (VVEngine.Simple.Scene): RenderTexture, ForwardPointLight/ForwardDirectionalLight/ForwardSpotLight stored only in the renderer's Scene, and the limits from shaders/simple_shared.h (for example 64 texture slots). That header also defines the shared shadow matrix ranges, point-face count, shadow near plane, occluded factor and receiver biases for C++ and Slang.
- Render/RenderResources.ixx: RenderScene, the CPU meshes, materials, instances, camera presence/imported owner tags and the texture table (a full table returns Error::capacity_exceeded, purgeUnusedAssets frees slots for reuse). Mesh, material and instance lookups use handle-to-index unordered maps, rebuilt after stable vector erasure or purge and emptied by clear(). Purge collects live handles in one instance pass and compacts each resource vector once. Texture acquisition checks the given path before canonicalizing a miss, caches decode errors until clear(), and retains the decode-time greyscale flag for HEIGHT-map checks. `RenderSystem::textureDecodeCount()` counts lifetime decode attempts, including failures and across clearScene(). Import traversal uses hashed node membership and visited sets. Light counts and presence queries read the renderer's Scene lists; backend owner tags retain per-instance light removal without a RenderScene light copy. `RenderSystem::clearLights()` clears those lists and their owner tags, preserving objects, resources, cameras and scene instances.
  `RenderTexture` retains its canonical path or `shared_ptr<const EmbeddedImage>` source. After each renderer frame, `releaseUploadedPixels` swaps away decoded storage only for matching nonzero `uploadedTextureGeneration` values; pending uploads retain their pixels. `RenderSystem::sceneTexturePixelBytes()` counts retained decoded bytes. Resident frames and resizes need no CPU pixels; re-upload after renderer reinitialization restores empty buffers through `textureForUpload`, preserving lifetime decode counts and cached failures. Missing files return `Error::io_error` through `std::expected`, with the decode error retained across the Vulkan boundary and cleanup. HEIGHT cache hits read only the stored greyscale flag. RenderTextureDedupTests covers release, capacity, source ownership, file re-upload and loss; RenderTextureOrientationTests verifies embedded re-upload pixels without the model file.
  `bindRenderScene` lends mutable storage solely for texture pixel restoration and decode bookkeeping (decoded extent/greyscale, attempt count and failure cache); `RenderSystem` owns pixel release. Reinitialization tests check validation errors before a new Vulkan instance resets the counter.
- Render/RenderSystem.ixx with RenderSystemObjects.cpp, RenderSystemScene.cpp and RenderSceneImport.cpp: simple::RenderSystem (objects, scene instances, lights, cameras, purging, mirroring into the renderer). Primitive caches use base colour/texture slot and shape/local extents; triangle meshes share only materials. Instance transforms carry placement. Editing shared geometry clones it; editing a sole primitive evicts its geometry cache entry. `removeObject` releases unreferenced non-imported meshes/materials and unused textures without a purge. Imported resources, including `default_material_` for materialless meshes, remain cached; cache hits verify resource existence after purging. `RenderPrimitiveSharingTests` checks these lifetimes without a window or GPU.
  `setPostProcessSetup` runs once per rendered window when its target is created; its `PostProcessing` and settings references stay valid until that window closes or the engine shuts down, including across resizes, and may be kept and changed at any time.
- Render/Renderer.ixx with RendererResources.cpp, RendererShadowPrep.cpp, RendererDraw.cpp and RendererDebug.cpp: ForwardRenderer (Vulkan bring-up and resource sync, shadow preparation, frame recording and present, shadow-depth samples (RenderShadowDepthSample from VVEngine.Types) and PNG capture).
  `prepareShadowFrame` fills the renderer's `FrameUniforms` directly; `frameUniforms()` exposes the latest window's prepared camera, packed light counts and shadow matrices. The shader iterates point lights up to `activePointLightCount`, stored in the former padding word without changing the uniform size. `ShadowLightMeta` retains the packed light index/type, per-type array layer, view/projection and near/far planes; spot layers are packed indices, point layers are packed index ×6 + face, and directional layers are packed index ×4 + cascade.
  ForwardRenderer owns an ordered `std::list<WindowTarget>`; stable addresses preserve the non-movable Vulkan RAII owners. The first rendered surface selects the device; each further surface must support presentation from the graphics queue or initialization returns `Error::platform_error` with a diagnostic. Every target builds uniforms and directional cascades from its stored camera and extent, renders shadows and colour, post-processes and presents in window order. `setCamera(Camera)` sets the current default; `setCamera(WindowHandle, Camera)` stores an optional override in one target, and `clearCamera(WindowHandle)` restores default fallback. Each target uses its own drawable aspect ratio. Assignments are supported after Engine::init, before lazy GPU initialization; pending overrides move into their targets on creation. Unknown, closed and opted-out windows return `Error::invalid_handle`. Window views and frame snapshots carry no ECS camera binding. The selected camera's clip planes drive projection and directional cascades, with defaults 0.1 and 100. RenderScene keeps only a bool for an explicitly set default camera and one owner tag per imported camera, preserving counts and per-instance removal; camera descriptors stay in the asset catalog. Shared shadow arrays are synchronized between windows. They grow without shrinking to packed light counts (directional ×4, spot ×1, point ×6; minimum one layer), retiring replaced arrays by graphics submission serial and marking every target's frame sets for rebinding after their own fences complete. Whole-image views are always 2D arrays, and every new layer is transitioned to shader-read layout once. Only positive-intensity lights clear and render shadow layers; lastShadowLayerPassCount() counts those passes for the last recorded window frame. Nonpositive-intensity point lights are omitted. Spot and directional lights with nonpositive intensity remain packed only for positive ambient, with normalized direction xyz and w = 1 to skip matrices, metadata, readback and shader PCF. Resizes replace only that window's resources; closed targets are released after `vkDeviceWaitIdle`, before shared device objects, without changing the `anyShouldClose` stop rule. GUI and mutable-format UNORM views belong only to the first rendered window, while events from all windows still reach InputState. `captureFrameToPng(WindowHandle, path)` selects a target; the original overload captures the first remaining rendered window.
  Frame fence waits use 1 s and image acquisition uses 100 ms. Fence timeouts and acquire VK_TIMEOUT/VK_NOT_READY return without submitting, increment skippedFrameCount() and do not log failures or count as presented frames. submitOnce is unchanged; vkQueuePresentKHR can still block.
  Scene sync runs after the target slot's fence wait. Replaced meshes, textures, buffers and shadow arrays enter a FIFO retirement queue tagged with the last successful graphics submission serial; completed fences reclaim covered owners across all windows on the shared graphics queue. Each target keeps materials and dynamic vertices per frame slot with dirty bitmasks, and writes only that completed slot's changed texture descriptor elements and pending shadow bindings. Device-idle waits go through one counted helper for resize, teardown and debug capture; scene updates and shadow growth add none. One-time uploads still wait for their fence. RenderRuntimeUpdateTests checks retirement, isolated slot contents and unchanged deviceWaitIdleCount() across mesh edits, texture replacement and shadow growth in two windows, with validation through cleanup.
  Frame submission waits for acquire at TRANSFER; the post-forward barrier includes TRANSFER in its source stages to order the swapchain layout transition. A frame without GUI vertices skips the GUI barrier and pass and presents from GENERAL using TRANSFER/TRANSFER_WRITE. `RecordedPass::post_process` marks an applied vvppl chain and `RecordedPass::gui` marks actual GUI recording. vvppl v1.0 has no public empty-chain query, so configured chains still run through `apply` even when empty.
  Shadow-depth samples are built and read back only when `setShadowDepthReadback(true)` is enabled; otherwise the rendered frame clears the sample list.
  `recordCommandBuffer` resolves one `std::vector<DrawItem>` per window frame and sorts it by mesh; pass loops use resolved buffers/materials without map lookups. `VulkanMesh` computes and caches its object-space culling box from vertices on create/updateVertices; each draw item encloses its transformed corners in a world AABB. `RenderMesh` stores no duplicate box. Each camera, spot, point-face and directional-cascade frustum rejects only strictly outside boxes; touching/intersecting and invalid bounds remain drawable. Vertex/index buffers bind only when the mesh changes across passes. The shadow pipeline, descriptor set and viewport bind once before the first layer. `lastFrameDrawStats()` counts forward/shadow draws and scene vertex-buffer/pipeline binds, excluding GUI and post-processing. SimpleForwardRendererTests checks culling, boundary contact, transforms, invalid bounds and dynamic edits; RenderMeshDedupTests checks one forward vertex-buffer bind for two shared instances.
- Vulkan/*.ixx (VVEngine.Simple.Vulkan partitions): Device, Presentation, Commands, Memory (VMA), Pipeline, Shadow, Resources, Readback, Handle.
  Command buffers are stored only in their RAII owners; recording and submission borrow those handles. The target owns the descriptor pool, while descriptor sets retain only their device and allocated handles. Validation-layer selection is local to instance creation. GUI preparation and recording use callbacks, and SDL event lookup uses WindowSystem's id-to-index map.
  Memory.ixx defines BufferMemory and the pure allocationInfoFor policy: device_local requires DEVICE_LOCAL without host access, upload uses SEQUENTIAL_WRITE plus MAPPED, and readback uses RANDOM plus MAPPED. Both mapped policies require HOST_VISIBLE and HOST_COHERENT. Static mesh vertices and indices use device-local buffers; one submitOnce copies both from staging buffers retained until the fence completes. Uniforms, per-slot materials and dynamic vertices, and texture/mesh staging stay on upload memory. VulkanReadback uses readback memory. VulkanMemoryPolicyTests checks the flags without a GPU; SimpleForwardRendererTests checks actual mesh and uniform allocation properties.
  VulkanImage stores mipLevels and covers all levels in its views. TextureImage records the base upload and per-level linear blits, falling back to one level when the format lacks linear filtering or either blit capability. One ForwardRenderer::materialSampler supplies linear min/mag/mip filtering, REPEAT and VK_LOD_CLAMP_NONE; anisotropy is enabled only when supported by the device. Cleanup destroys it after device idle. VulkanUploadBatch owns staging buffers and one command buffer through a single fence wait; uploadSceneTextures batches all new images of one sync and commits their generations only on success. Texture changes and removals retain per-slot descriptor updates and serial retirement without device-idle waits. textureUploadSubmitCount() counts successful batches, including the initial fallback image. VulkanTextureTests checks fallback policy, rectangular sRGB/linear mip pixels, sampler lifetime and validation through cleanup.
- shaders/simple_forward.slang and shaders/simple_shared.h: forward vertex, fragment and shadow vertex stages, compiled by slangc into generated uint32_t SPIR-V headers during the build (target vve_simple_shaders). Only RendererResources.cpp includes the headers, embedding all three stages in the engine binary; shader files are not loaded at runtime. Changes to either source regenerate the headers and rebuild the engine.
  The material buffer is fragment-only; vertex outputs carry geometry and UVs without a colour varying. Unlit fragments return the sampled base colour before other material samples or lighting, using the uniform per-object push constant.

## Tests

- `VVE.TestSupport` in `tests/support/TestSupport.ixx` shares hidden-engine setup and capture/fixture helpers. `hiddenEngine(name, extent[, max_frames])` returns an uninitialized simple engine with one hidden forward window named `main`; tests retain their own initialization checks and link `vve_test_support`.
- MultiWindowRenderTests checks two hidden forward windows, renderer opt-out and invalid ids, per-window PNG sizes, independent cameras, live default fallback, clearing overrides, camera uniforms, directional cascades and central geometry, separate post-processing settings, GUI ownership, independent resize, one shared pipeline and zero validation errors through target shutdown.
- RenderResizeTests resizes a hidden window, checks drawable and PNG extents, forwardPipelineCreateCount() == 1 and zero validation errors; drivers that ignore the resize use explicit swapchain recreation instead.
- GuiColorCaptureTests renders authored grey (128,128,128) into a hidden window and requires PNG channels within ±2 on the mutable-format path, before and after swapchain recreation, with zero validation errors. GuiSystemTests checks theme preservation on UNORM and one-time theme linearization for the sRGB fallback without a GPU.
- VulkanDeviceRequirementsTests imports VVEngine.Simple.Vulkan and checks the pure evaluateDeviceRequirements function with synthetic capabilities; it creates no Vulkan objects and has no gpu label.
- RenderAcquireActionTests imports VVEngine.Simple.Renderer and checks the pure acquireAction mapping without Vulkan objects or a gpu label. SimpleForwardRendererTests requires skippedFrameCount() == 0 during normal rendering.
- RenderFrameCountTests checks Error::not_initialized before renderer initialization and presented/skipped-frame accounting through hidden 64×64 windows; it carries the gpu label. Two-window minimization and restoration preserve targets, swapchains, camera overrides, post-processing chains and GUI ownership. RenderSystem counts frames and FPS only after presentation, and a frame counts once when at least one target presents; lastRenderedWindowCount counts the targets actually presented and is zero when all windows are skipped.
- White-box tests import VVEngine.Simple directly and link Vulkan::Vulkan (see tests/CMakeLists.txt). With simple::Engine pass vve::simple::Windows, not vve::WindowSetups; use WindowDesc{.visible = false} for hidden windows that still render.
